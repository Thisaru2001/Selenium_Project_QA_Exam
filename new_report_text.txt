1. Introduction
1.1 Purpose of the Project
A small online retail team requires a beginner-level automated smoke and regression suite for its demonstration shopping website, DemoBlaze. The purpose of this project is to design, develop and execute that suite using Java, Maven, Selenium WebDriver and TestNG. The suite confirms that customers can open the store, browse phone products, view product information, add products to the cart, remove an unwanted product and complete basic checkout validation.
1.2 Scope of the Automation
The automated solution covers the following functions of https://www.demoblaze.com/:
Home-page title and PRODUCT STORE heading verification
Phones category selection
Samsung galaxy s6 product selection and price retrieval
Add to cart action and JavaScript alert handling
Cart product counting using findElements()
Printing product names and prices using a loop
Removing Nokia lumia 1520 and confirming Samsung galaxy s6 remains
Cart total verification
Valid purchase-form submission using fictitious test data
Invalid purchase-form validation when mandatory details are missing
1.3 Test Site and Data Policy
Test site: https://www.demoblaze.com/
Only fictitious test data is used. No real payment-card details or personal information are entered at any point.
The site is a public demonstration site, so its data may change. Assumptions and any observed limitations are documented in Section 8.
1.4 Learning Objectives Demonstrated
This project demonstrates the ability to:
Translate a web-testing scenario into clear automated test cases.
Create and run a Java, Maven, Selenium WebDriver and TestNG project.
Use reliable locators and interact correctly with web elements.
Apply assertions to verify expected results.
Use explicit waits instead of unnecessary fixed delays.
Handle JavaScript alerts, collections of elements and cart content.
Implement both a valid workflow and a simple invalid validation scenario.
Close the browser safely and explain the completed code.

4.2 Class Design
4.3 Setup and Cleanup
@BeforeMethod creates a new ChromeDriver, maximizes the window, creates the WebDriverWait and navigates to the base URL, so every test starts from a clean session with an empty cart. @AfterMethod(alwaysRun = true) quits the browser after every test, including tests that fail, which guarantees that no browser process is left running.
import org.openqa.selenium.OutputType;
import org.openqa.selenium.TakesScreenshot;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.openqa.selenium.support.ui.WebDriverWait;
import org.testng.annotations.AfterMethod;
import org.testng.annotations.BeforeMethod;

import java.io.File;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.StandardCopyOption;
import java.time.Duration;

public class BaseTest {

    protected WebDriver driver;
    protected WebDriverWait wait;

    // Reusable Data (Class-level constants)
    protected static final String BASE_URL = "https://www.demoblaze.com/";
    protected static final String PRODUCT_SAMSUNG = "Samsung galaxy s6";
    protected static final String PRODUCT_NOKIA = "Nokia lumia 1520";
    
   protected static final String CHECKOUT_NAME = "Test Student";
    protected static final String CHECKOUT_COUNTRY = "Sri Lanka";
    protected static final String CHECKOUT_CITY = "Colombo";
    protected static final String CHECKOUT_CARD = "4111111111111111";
    protected static final String CHECKOUT_MONTH = "12";
    protected static final String CHECKOUT_YEAR = "2027";

    @BeforeMethod
    public void setUp() {
        // Setup Chrome driver
        driver = new ChromeDriver();
        
       // Initialize explicit wait for 10 seconds
        wait = new WebDriverWait(driver, Duration.ofSeconds(10));
        
       // Maximize browser window
        driver.manage().window().maximize();
        
       // Navigate to the base URL
        driver.get(BASE_URL);
    }

    @AfterMethod(alwaysRun = true)
    public void tearDown() {
        // Safe cleanup of browser session
        if (driver != null) {
            driver.quit();
        }
    }

   
   protected void takeScreenshot(String fileName) {
        try {
            File srcFile = ((TakesScreenshot) driver).getScreenshotAs(OutputType.FILE);
            File destFile = new File("screenshots/" + fileName + ".png");
            Files.copy(srcFile.toPath(), destFile.toPath(), StandardCopyOption.REPLACE_EXISTING);
            System.out.println("Screenshot saved: " + destFile.getPath());
        } catch (IOException e) {
            System.out.println("Failed to save screenshot: " + e.getMessage());
        }
    }
}

5. Locator Strategy
5.1 Approach
Locators were chosen so that they are readable, unique and unlikely to break when the page layout changes.
id is used wherever an element has a unique id, because it is the fastest and most stable strategy.
linkText is used for simple navigation links whose visible text is unique.
Relative XPath with text or attributes (normalize-space(), contains(), @id, @class) is used for all other elements. Absolute XPath and position-based indexes are avoided because they break easily.

6. Implementation
6.1 Browser Control
Chrome is opened through Selenium WebDriver, maximized and pointed at the base URL. The session is always closed with driver.quit() in the cleanup method, which ends the whole browser session and the driver process (close() would only close the current window).
Listing 5: Opening, maximizing and quitting Chrome
6.2 Explicit Waits
Explicit waits (WebDriverWait with ExpectedConditions) are used instead of Thread.sleep(). A fixed sleep always pauses for the full time, wasting time when the page is fast and still failing when the page is slower than expected. An explicit wait polls until the condition is true or the timeout expires, then continues immediately.

6.5 Collections and Loops
findElement() returns a single WebElement and throws NoSuchElementException if nothing matches, whereas findElements() returns a List<WebElement> that is empty when nothing matches. In TC04, findElements() collects the cart rows so that they can be counted with size() and processed with a loop that prints each product name and price.

8. Issues and Limitations
8.1 Public-Site Changes
DemoBlaze is a public demonstration site. Product names, prices, page text and alert wording may change without notice, and the site may be slow or temporarily unavailable. To reduce this risk, prices are read from the page instead of being hard-coded, alert assertions use the key phrase with contains(), and locators are based on ids and visible text. 8.2 Timing Issues
The site loads product lists and cart rows dynamically. Clicking or reading elements too early can cause failures such as NoSuchElementException, ElementClickInterceptedException or NoAlertPresentException. These are prevented by explicit waits instead of fixed delays. Observed timing problems: [Describe or write "None observed"].

9. Conclusion
This project delivered a Selenium Java automation suite for the DemoBlaze web store using Maven and TestNG. The five automated scenarios cover the home-page smoke test, product selection and price retrieval, add to cart with JavaScript alert handling, cart management with findElements() and a loop, and checkout validation with both an invalid and a valid submission.
Explicit waits were used for elements and alerts, reliable XPath and id / linkText locators were applied, assertions verified titles, headings, URLs, alert messages, cart contents and success states, and @AfterMethod(alwaysRun = true) guaranteed that the browser was closed after every test.
